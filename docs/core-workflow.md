# 핵심 기능 사용 및 운영 기준

구현 기준: [기획 12절의 2단계 및 첫 출시 범위](overtime-approval-plan.md). 개발과 검증은 `compose.dev.yaml`의 Python 3.12 / Django 5.2 / PostgreSQL 17 컨테이너 안에서 수행한다.

## 최초 설정

1. [Entra 설정](entra-sso.md)과 마이그레이션 적용 후 최초 관리자가 SSO 로그인하고 `bootstrap_entra_admin <사용자-Object-ID> --superuser` 명령으로 권한을 부여한다.
2. `/setup/`에서 부서를 만든다. 부서장은 사용자 생성 후 지정한다.
3. 직원에게 첫 SSO 로그인을 안내하여 계정을 자동 생성한 뒤 사번·소속·역할·소정근무 요일·일 소정근무 시간을 지정한다. 기본은 월~금, 일 480분이다.
4. 부서에 부서장을 지정한다. 자동 승인자는 일반 사용자 → 소속 부서장, 부서장 → 기본 최고관리자, 최고관리자 → 본인 순으로 정한다. 직접 지정한 승인자가 있으면 우선한다. 최고관리자가 여러 명이면 기초정보의 기본 최고관리자를 설정한다. 직원과 부서장의 사번·활성 부서·승인자 설정 후 ‘업무 설정 완료’를 체크한다. 그전에는 대기 화면만 이용할 수 있다.
5. 적용 시작일과 월 무승인 기준을 정책으로 등록한다. 16시간은 960분이다. 적용 가능한 정책이 없으면 제출을 차단한다.
6. 휴일을 등록한다. 휴일과 비근무 요일의 실제 근무는 전체를 초과 근무로 계산한다.

일반 관리자도 기초정보를 관리할 수 있다. Django 관리 페이지는 슈퍼유저 전용이며 계획·실적·결재 이력은 조회만 허용한다. 일반 관리자는 슈퍼유저 계정을 변경할 수 없다. 계정의 관리자 역할과 결재 권한은 분리된다. 기초정보 변경 항목과 처리자는 Django 관리 로그에 기록한다.

## 직원의 계획 및 결재

1. **계획 등록**에 날짜, 시작·종료, 휴게, 업무명, 사유를 입력한다. 야간 근무는 종료일을 입력한다.
2. **제출 전 계산**으로 월별 기존 누적·이번 시간·제출 후 누적·기준·남은 시간·예상 상태와 승인자를 확인한다. 미리보기는 저장하지 않으며 제출할 때 다시 계산한다.
3. **임시 저장**은 누적에서 제외한다. **제출**하면 기준 이내는 무승인 확정, 초과는 신규 계획 전체가 승인 대기가 된다. 월별 확정·승인·승인 대기 시간을 합산한다.
4. 지정 승인자는 **결재함**에서 업무·사유·월별 제출 근거·같은 달 계획·실적·변경 전후 이력을 확인하고 승인 또는 반려한다. 반려 사유는 필수다.
5. 승인 대기는 **회수**한 뒤 수정한다. 확정·승인 완료 계획의 수정은 기존 버전과 승인을 이력에 보존하고 다시 기안한다. 임시 저장으로 바꾸면 누적에서 제외된다.
6. 반려 후 수정·재제출할 수 있다. 취소는 이력을 남기며 실적 연결도 유지한다. 반려·취소 때문에 다른 대기 계획을 자동 확정하지 않는다.

본인 계획만 수정할 수 있고, 최고관리자(is_superuser)만 자기 신청을 결재할 수 있다. 기준 초과 제출 후 결재함에서 직접 승인한다. 부서 이동이나 부서장 변경 후에도 기존 계획의 소속과 결재 담당자는 유지한다. 관리자 열람 권한만으로 결재할 수 없다. 결과와 회수·취소 알림은 시스템 안에 표시한다.

## 실제 근무 입력

**실적 등록**에는 하루 전체 출퇴근과 휴게를 입력한다. 실제 근무 시간은 출퇴근 차이에서 휴게를 차감하고, 실제 초과 근무는 날짜별 순근무에서 해당 사용자의 소정근무 시간을 차감해 계산한다. 소정근무 기준은 기록에 함께 보존하며 이후 기준 변경만으로 과거 실적을 다시 계산하지 않는다.

- 동일 날짜는 하나의 전체 근무 기록으로 관리한다. 중복 날짜가 있으면 기존 기록을 수정한다. 실적 수정에는 별도 수정 사유가 필요하다.
- 본인의 계획을 연결한다. 실제 근무 날짜와 계획 날짜가 겹쳐야 한다.
- 미계획 초과 근무 또는 연결 계획 전체 실적의 합이 계획 시간을 초과하면 사유가 필요하다.
- 승인 대기·반려·취소·임시 저장 상태의 계획에도 실제 근무를 기록할 수 있다. 근무 시작 전에 확정·승인되지 않았다면 사전 승인 미완료로 표시한다. 소급 승인으로 이 표시를 제거하지 않는다.
- 조회 화면에서 계획별 실적과 계획 대비 차이, 미계획 실적과 승인 미완료 상태를 확인한다.
- 구버전의 수동 초과 근무 수치는 마이그레이션에서 그대로 보존한다. 기존 데이터의 소정근무 기준은 알 수 없으므로 새로 계산하지 않는다.

## 시간 배분과 조회

한 계획·실적은 최대 7일까지 입력할 수 있다. 자정을 기준으로 일별·월별 시간을 배분하고, 휴게는 구간 끝에서 차감한다. 휴게가 월 경계 이전에 실제로 발생해 월별 배분이 달라져야 한다면 날짜별 기록으로 나누어 입력한다. 월별 정책은 해당 월의 첫 계획 근무일에 유효한 정책을 사용하며 제출 당시 정책과 판단을 보존한다.

**근무 현황**에서 월·부서·사용자·계획 상태·실적 등록 여부를 검색한다. 일반 사용자는 본인, 부서장은 저장된 소속 부서와 본인, 관리자는 전체 기록을 열람한다. 부서장 본인 신청의 외부 지정 승인자는 자신에게 지정된 계획과 연결 실적을 열람할 수 있다. 부서 이동 후 다른 부서의 기록이 기존 부서장에게 노출되지 않는다.

## 남은 후속 단계

3단계: 기간별 조직·근무 일정 이력, 대결·결재 이관·마감, 엑셀 다운로드, 미처리 독촉 및 예외 알림 확대. 현재 근무 일정은 사용자별 요일·일 소정근무 시간이며 교대·유연근무와 기간별 일정은 포함하지 않는다.

4단계: 외부 근태 API, 자동 입퇴사·조직 동기화, 메신저 연동 및 충돌·재처리 정책. Entra 회사 계정 로그인은 구현했다. 외부 API 입력은 아직 제공하지 않는다. 첨부파일·프로젝트 선택은 선택적 확장 범위로 남아 있다.
