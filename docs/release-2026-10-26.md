# OMS 2026-10-26 배포 준비

대상: Synology ARM64 + Cloudflare Tunnel. 앱 이미지: `oms:2026.10.26-a719fb5`.
업무 코드 기준은 `a719fb5`이며, 이번 준비에서 Docker 의존성을 `requirements.lock`으로 고정했다.
실제 NAS 배포와 외부 공개는 아직 수행하지 않았다.

## 준비한 파일

`dist/oms-2026.10.26-a719fb5/`에 다음 파일을 준비한다.

- `images-arm64.tar`: 앱, PostgreSQL 17, cloudflared 2026.10.3 ARM64 이미지
- `compose.cloudflare.yaml`, `.env.cloudflare.example`, `requirements.lock`
- `docs/`: 이 절차와 Cloudflare·Synology·Entra·Teams 운영 문서
- `manifest.json`: 이미지 ID와 소스 기준
- `SHA256SUMS`: 파일 전송 무결성 확인용 체크섬

실제 `.env`, 터널 토큰, DB 및 사용자 파일은 배포 묶음에 포함하지 않는다.
로컬 `.env`에는 기존 Entra callback을 기준으로 `oms.pingsns.com`을 허용 호스트와 CSRF origin에 반영했고,
릴리스 이미지 태그와 새 무작위 Django 비밀키를 설정했다. `.env` 권한은 600이다.
이 키를 기존 서비스에 적용하면 기존 세션이 무효화될 수 있다.
운영 DB 비밀번호와 Entra 자격 증명은 변경하지 않았다.

## 검증 결과

- ARM64 Python 3.12 앱 이미지 빌드·정적 파일 수집 성공
- 격리된 `oms-release-verify` PostgreSQL에서 전체 87개 테스트 통과
- 최초 마이그레이션부터 `core.0005`까지 적용 성공, 추가 마이그레이션 누락 없음
- 운영 Gunicorn HTTP 검사 통과: DB health, HTTPS 리다이렉트, 정적 자산, 로그인 요구, 관리자, CSRF, 로그아웃, media 쓰기
- 실제 로컬 `.env`의 `check --deploy --fail-level ERROR` 통과
- `pip check` 통과, 두 운영 Compose 구문 검사 통과
- HSTS 미설정 경고 1개 유지. 실제 HTTPS 운영을 확인한 후 적용을 결정한다.

HTTP 인증 검사는 서버가 만든 임시 세션을 사용했다. 실제 Entra 계정 로그인, MFA, Cloudflare DNS·TLS·터널,
NAS 실기기 및 운영 데이터의 백업·복구는 검증하지 않았다. 기존 `oms` 프로젝트의 DB는 변경하지 않았다.
Teams는 현재 `.env`의 `TEAMS_ENABLED=0`을 유지한다.

## NAS 적용 절차

1. NAS의 기존 프로젝트 이름·볼륨과 배포 경로를 확인한다. 아래 `-p oms`는 해당 볼륨을 사용하는 경우의 예시다.
   기존 서비스 업데이트라면 먼저 쓰기를 중지하고 DB와 media를 백업한다.
2. 배포 폴더에 묶음을 복사한 뒤 아래 명령으로 파일과 이미지를 확인한다.

```sh
sha256sum -c SHA256SUMS
docker load -i images-arm64.tar
```

3. 준비한 로컬 `.env`를 안전한 경로로 NAS 배포 폴더에 별도로 복사하고 `chmod 600 .env`를 적용한다.
   기존 NAS DB가 있다면 해당 DB의 이름·사용자·비밀번호와 일치하는지 먼저 확인한다.
   템플릿을 사용할 경우 모든 비밀값과 Entra 값을 직접 설정한다.
4. Cloudflare에서 `oms.pingsns.com`의 공개 route를 `http://app:8000`으로 구성하고,
   터널 connector token 한 줄을 `secrets/cloudflared-token`에 저장한다.
   이 파일은 로컬에서 아직 준비되지 않았다. 디렉터리 권한 700, 파일 권한 444를 적용한다.
   Cloudflare HTTPS 강제·캐시 우회와 Entra Web callback 등록은 각 운영 문서를 따른다.
5. 같은 프로젝트 이름과 Compose 파일로 DB 및 앱을 순서대로 실행한다.

```sh
docker compose -p oms -f compose.cloudflare.yaml config --quiet
docker compose -p oms -f compose.cloudflare.yaml up -d --wait db
docker compose -p oms -f compose.cloudflare.yaml run --rm app python manage.py migrate --noinput
docker compose -p oms -f compose.cloudflare.yaml run --rm app python manage.py check --deploy --fail-level ERROR
docker compose -p oms -f compose.cloudflare.yaml up -d --wait app
docker compose -p oms -f compose.cloudflare.yaml up -d --wait cloudflared
docker compose -p oms -f compose.cloudflare.yaml ps
```

6. 외부 네트워크에서 `https://oms.pingsns.com/health/`, 실제 SSO 로그인·접근 거부·로그아웃을 확인한다.
   첫 관리자 로그인 후 [Entra 운영 문서](entra-sso.md)에 따라 권한과 기초정보를 설정한다.

업데이트·복구·터널 토큰 교체는 [Cloudflare 배포 문서](deployment-cloudflare.md)와
[Synology 배포 문서](deployment-synology.md)를 따른다. DB 스키마와 호환되는 이전 앱 이미지 또는
검증한 백업으로 복구하며, 영구 볼륨을 삭제하는 `down -v`는 사용하지 않는다.
