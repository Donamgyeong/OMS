# 휴일 동기화 및 기본 결재자 개선 계획

작성일: 2026-10-28. 구현 전 계획이며, 현재 실행 코드는 변경하지 않는다.

## 1. 목표와 해석

Microsoft 365의 회사 휴일 캘린더를 OMS에 동기화하고, 구성원 설정 화면과 실제 기안에서 같은 기본 결재자 규칙을 사용한다.

| 신청자 | 기본 결재자 |
|---|---|
| 일반 사용자 | 소속 부서의 활성 부서장 |
| 부서장 | 활성 최고관리자 |
| 최고관리자 | 본인 |

최고관리자는 현재 모델의 `is_superuser=True`로 해석한다. `role=admin`만 가진 운영 관리자는 최고관리자로 승격하지 않으며, 기본적으로 소속 부서장 경로를 적용한다. 실제 부서의 `head`인 사용자도 부서장 경로를 적용하고, 역할과 부서 설정이 불일치하면 설정 화면에서 경고한다. 최고관리자 판정을 가장 먼저 적용한다.

자기 결재는 기준 초과 제출 → 승인 대기 → 본인이 승인 버튼으로 처리하는 방식으로 계획한다. 제출 즉시 자동 승인하는 것으로 해석하지 않는다. 기존 월별 무승인 기준 이내 제출은 그대로 무승인 확정한다.

## 2. 현재 구현과 변경 지점

- `Holiday`는 날짜·이름만 보관하고 `HolidayForm`으로 수동 등록한다. 실적 계산은 이 테이블의 날짜를 사용한다.
- `resolve_approver()`는 지정 승인자, 부서장, 상위 부서장 순으로 처리한다. 부서장의 최고관리자 기본 선택은 없다.
- `MemberForm`은 본인을 선택지에서 제외하고 `User.clean()`은 본인 지정을 금지한다.
- `transition_plan()`과 상세·결재 목록 화면도 본인 결재를 차단한다. 선택값만 바꾸면 실제 승인까지 이어지지 않는다.

## 3. MS 캘린더 휴일 동기화

### 연동 원본과 인증

1. 회사 휴일만 관리하는 Exchange Online 사서함의 전용 캘린더를 원본으로 지정한다. Outlook에서 보이는 구독형 국가 휴일 캘린더가 Graph에서도 조회되는지는 실제 테넌트에서 먼저 확인한다. 조회되지 않으면 전용 캘린더에 휴일을 등록한다.
2. 로그인용 OIDC scope와 구분해 서버 배치용 Graph 인증을 설정한다. 읽기 전용 최소 권한은 공식 API 문서의 `Calendars.ReadBasic`부터 검증하며, 선택한 원본과 필요한 필드에 따라 확정한다. 관리자 동의와 해당 사서함으로 접근 범위 제한을 구성한다.
3. 대상 사서함·캘린더 ID, 시간대, 조회 기간을 설정한다. 실제 연결 단계에서 테넌트 설정과 원본 ID가 필요하며 계획 작성에는 필요하지 않다.

### 수집과 저장

1. `calendarView`로 전년도부터 다음 연도까지 조회한다. 반복 일정의 발생분과 예외, 전체 페이지를 처리한다.
2. 전용 캘린더의 취소되지 않은 종일 일정만 휴일로 반영한다. 서울 시간 기준 날짜로 정규화하고 종료일은 제외해 여러 날 휴일을 펼친다. 일반 회의나 개인 일정은 포함하지 않는다.
3. 원본 캘린더·이벤트·발생일 식별자와 동기화 시각을 별도 원본 테이블에 저장하고, 기존 날짜별 `Holiday`에 집계한다. 날짜가 같은 여러 이벤트와 수동 등록 휴일이 충돌하지 않도록 수동 이름·설정을 우선한다.
4. 원본 수정·삭제·취소를 반영하되, 조회 범위의 모든 페이지를 성공적으로 수집한 뒤 한 트랜잭션에서 갱신한다. 부분 실패나 인증 오류 시 기존 휴일을 유지한다. 수동 휴일은 동기화 삭제 대상에서 제외한다.
5. 관리 명령과 매일 1회 배치를 추가하고 관리자 화면에 수동 동기화, 마지막 성공 시각, 반영 건수, 오류를 표시한다. 재시도와 중복 실행 방지를 제공한다.
6. 이미 저장된 실적의 계산값은 자동 소급 변경하지 않는다. 변경 휴일이 기존 실적에 영향을 주면 대상 목록을 제공하고, 기존 감사 이력을 남기는 재계산 절차로 처리한다.

## 4. 기본 결재자와 예외 지정

1. 공통 기본 결재자 해석 함수를 만들고 설정 화면·미리보기·제출에 재사용한다.
2. 지정 승인자는 ‘자동(역할 기준)’과 ‘직접 지정’을 구분한다. 자동을 기본으로 하고 실제 결재자와 선정 사유를 표시한다. 기존 명시적 지정은 유지한다. 최고관리자는 본인을 기본으로 표시하며, 일반 사용자와 부서장의 본인 직접 지정은 계속 금지한다.
3. 부서장용 최고관리자는 활성 최고관리자가 한 명이면 자동 선택한다. 여러 명이면 조직의 기본 최고관리자 설정을 사용한다. 선택이 없거나 비활성 상태면 명확한 오류를 표시하며 임의의 첫 사용자를 선택하지 않는다.
4. 신규·편집 화면에서 부서나 역할 변경 시 자동 기본값을 다시 표시한다. 직접 지정값은 의도 없이 덮어쓰지 않는다. 서버도 동일한 규칙으로 검증하며, 저장된 외래 키에 자동값을 복사해 조직 변경 후 낡은 값이 남는 방식은 피한다.
5. 최고관리자 자기 결재 허용 조건을 공통 권한 함수로 묶는다. 서버 전이, 상세 버튼, 결재 목록, Teams 카드·처리 경로와 알림을 점검한다. 비최고관리자의 자기 결재는 거절한다.
6. 제출 당시의 결재자와 선정 근거를 이력에 보존한다. 부서 이동·부서장 변경·기본 최고관리자 변경이 기존 승인 대기 및 완료 건의 담당자를 자동 변경하지 않도록 한다. 자기 승인 시점에도 활성 최고관리자 자격을 검증한다.

## 5. 구현 순서와 검증

1. 결재자 공통 규칙·기본 최고관리자 설정·자동/직접 지정 표시를 구현한다. 기존 지정값은 보존하고, 자동 적용 시 결재자가 없는 사용자와 복수 최고관리자 예외를 사전 점검한다.
2. 자기 결재 권한과 관련 화면·알림을 수정하고 기존 업무 흐름 문서를 갱신한다.
3. 휴일 원본 모델·마이그레이션·Graph 클라이언트·동기화 명령·관리 화면·배치를 구현한다.
4. 역할별 기본값, 역할 중첩, 복수/비활성 최고관리자, 부서장 미지정, 직접 지정 유지, 최고관리자 자기 승인과 일반 사용자 자기 승인 거절, 중복 처리, 기존 결재자 보존을 검증한다.
5. 휴일 중복·반복·여러 날·시간대·삭제·취소·페이지 실패·재실행·수동 휴일 보존·기존 실적 보존을 검증한다. 실제 테넌트에서 조회와 배치 재인증을 확인한 뒤 운영 연결한다.
