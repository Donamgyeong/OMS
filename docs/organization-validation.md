# 사용자·부서 입력 규칙

사용자 역할과 부서장 지정을 한 트랜잭션으로 저장한다. 기초정보와 Django 관리자 화면은 같은 저장 서비스를 사용하며, 연동으로 변경된 사용자·부서도 관리자 변경 이력에 남긴다. 이미 제출한 계획의 소속·결재자는 변경하지 않는다.

## 변경 동작

- 사용자를 활성 부서장으로 설정하면 소속 부서의 부서장도 지정된다. 활성 소속 부서가 필수다.
- 이미 다른 부서장 또는 부서장 역할 사용자가 있으면 사용자 화면에서 덮어쓸 수 없다. 부서 화면에서 담당자를 명시적으로 교체한다.
- 부서 화면에서는 해당 부서의 활성 사용자만 부서장으로 선택한다. 지정된 사용자를 부서장 역할로 변경하고, 이전 담당자는 일반 사용자로 변경한다. 최고관리자 권한은 유지한다. 운영 관리자 역할을 암묵적으로 해제하지 않으며 먼저 사용자 화면에서 역할을 정리해야 한다.
- 부서장이 이동·비활성화되거나 부서장 역할을 해제하면 이전 부서장 연결을 제거한다. 부서장 없이 남은 부서는 후임자를 지정해야 자동 결재가 가능하다.
- 업무 설정 완료 사용자는 변경 후에도 사번·활성 부서·유효한 승인자가 필요하다. 담당자 해제 등으로 이 조건이 깨지면 저장 전체를 취소한다. 먼저 후임자를 지정하거나 업무 설정 완료를 해제해 설정을 정리한다.
- 활성 사용자나 활성 하위 부서가 남아 있으면 부서를 비활성화할 수 없다. 먼저 소속 이동·비활성화 또는 상위 부서 변경이 필요하다.
- 자기 자신 또는 하위 부서를 상위 부서로 지정할 수 없다. 활성 부서의 상위 부서도 활성 상태여야 한다.
- 운영 관리자는 최고관리자의 역할을 직접 또는 부서장 변경을 통해 간접 변경할 수 없다.

## 입력 검증

사번의 앞뒤 공백은 제거하며, 비어 있는 사번은 NULL로 통일한다. 중복 사번은 거절한다. 부서명의 공백도 제거하며 빈 이름과 중복 이름은 거절한다. 소정근무는 하루 1~1440분, 근무 요일은 중복 없는 0~6으로 입력한다. 지정 승인자는 활성 상태이며 소속 부서가 있다면 활성 부서여야 한다. 최고관리자 외 자기 지정은 거절한다.

웹 입력은 조회 당시 변경 지문을 숨김 필드로 전송한다. 잠금 후 현재 값과 비교해 오래된 화면의 덮어쓰기를 거절한다. 기존 호출 호환성을 위해 지문 없는 입력도 허용하지만 저장 시 조직 잠금과 모든 검증을 다시 적용한다. 조직 정보는 ORM `update()`로 직접 변경하지 않고 저장 서비스를 사용한다.

## 기존 불일치 점검과 복구

```sh
python manage.py audit_organization
```

조회만 수행한다. 단독 활성 부서장 역할 사용자가 있으나 부서장이 비어 있는 경우, 또는 부서장은 지정됐으나 역할만 일반 사용자인 경우에는 다음 명령으로 복구할 수 있다.

```sh
python manage.py audit_organization --repair --actor <활성 최고관리자 사용자 ID>
```

복수 담당자, 다른 부서 소속, 비활성 담당자, 운영 관리자 등 판단이 필요한 데이터는 자동 복구하지 않고 수동 확인 대상으로 출력한다. 복구는 일반 저장과 같은 검증·감사 이력을 적용한다. 실제 운영 DB에 대한 점검·복구는 배포 환경에서 실행해야 한다.
